# API Sözleşmeleri

Ajan başına dışarıya açılan uç noktalar. Detaylı akışlar için bkz. `sequence-diagrams.md`, veri modelleri için bkz. `data-schema.md`.

**Kimlik ve sahiplik:** `/health`, `/auth/kayit`, `/auth/giris`, `/auth/eposta-dogrula` ve token'lı referans uçları (`GET /dogrulama/referans/{token}`, `POST /dogrulama/referans-yaniti`) dışındaki her uç nokta `Authorization: Bearer <token>` ister. 401 token yok/geçersiz, 403 rol uygun değil, 404 başkasının kaynağı (varlığı sızmasın diye 403 değil). Uç nokta başına kim erişir tablosu: `kimlik-ve-dongu.md` § 3; kurallar `backend/app/api/sahiplik.py`'de.

**Eşleşme durumları** (kimlik-ve-dongu.md § 5): kural tek yerde, `app/agents/eslesme_durumu.py` › `gecis()`. Tablo dışı geçiş 409 ve mevcut durumu söyler; aynı geçişin tekrarı 200, yan etkisiz. **Eşleşmeden sonra e-posta:** karşılıklı ilgi kesinleşince (`ilgileniyorum`'un karşılıklı kolu, `kabul`, `firma-kabul`) bildirimi alan tarafa yanıttan sonra arka planda bir "eşleştiniz" e-postası gider (`app/servisler/eslesme_epostasi.py`); gövdede karşı tarafın adresi yok, yalnızca iş birliği sayfasının bağlantısı. Gönderim hatası akışı düşürmez. `kabul_edildi`'de arayüz ayrıca **"E-posta yaz"** düğmesi gösterir: kişinin kendi e-posta programını hazır bir taslakla açan `mailto:` bağlantısı (`frontend/src/lib/eposta-taslagi.ts`; firma→genç, genç→firma, firma↔firma; LLM yok, şablon; bağlantı 1500 karakteri geçmez). Uç yalnızca taslak alanlarını (`basari_kriteri`, `calisma_basligi`) döner, e-posta adresi yine yalnızca `iletisim`'de.
